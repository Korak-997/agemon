# Releasing agemon to npm

This document describes the complete release process for this repository, including:

- prerelease channels (`alpha`, `beta`)
- stable releases (`vX.Y.Z`)
- changelog generation with Changesets
- automated publishing through GitHub Actions
- CI guards that prevent incomplete releases

## Release model

This repository publishes only from Git tags. Merging to `master` alone does not publish.

Allowed tag formats:

- `vX.Y.Z-alpha.N`
- `vX.Y.Z-beta.N`
- `vX.Y.Z`

Examples:

- `v0.2.0-alpha.0`
- `v0.2.0-beta.1`
- `v0.2.0`

Channel mapping to npm dist-tags:

- `*-alpha.*` -> `alpha`
- `*-beta.*` -> `beta`
- stable (`X.Y.Z`) -> `latest`

## Tooling in this repo

- Changesets CLI (`@changesets/cli`)
- npm package scripts:
  - `npm run changeset`
  - `npm run version-packages`
  - `npm run release`
- GitHub workflow: `.github/workflows/release.yml`

## How changelogs are generated

Changelogs are generated by Changesets during versioning, not during `npm publish`.

Flow:

1. Add a changeset file for user-facing changes:
   - `npm run changeset`
2. Aggregate changesets into a version bump and changelog entry:
   - `npm run version-packages`
3. Commit generated files (including `CHANGELOG.md` and updated `package.json`).
4. Tag and push.
5. CI publishes from that tag.

Important:

- If you skip `npm run version-packages`, CI will fail the release guard.

## Day-to-day contributor workflow

For each PR with user-facing changes:

1. Run `npm run changeset`.
2. Select bump type (`patch`, `minor`, or `major`).
3. Write concise release notes.
4. Commit the generated `.changeset/*.md` file with your code changes.

## Maintainer release workflow

### 1. Sync and verify

```bash
git checkout master
git pull --ff-only
npm ci
npm run lint
npm run typecheck
npm test
npm run build
```

### 2. Generate version and changelog

```bash
npm run version-packages
```

This consumes pending `.changeset/*.md` files and updates:

- `package.json` version
- `CHANGELOG.md`

Then commit:

```bash
git add .
git commit -m "release: version packages"
```

### 3. Create release tag

Choose one of these paths.

Alpha:

```bash
npm version 0.2.0-alpha.0
git push origin master --follow-tags
```

Next alpha iteration:

```bash
npm version prerelease --preid alpha
git push origin master --follow-tags
```

Beta:

```bash
npm version 0.2.0-beta.0
git push origin master --follow-tags
```

Next beta iteration:

```bash
npm version prerelease --preid beta
git push origin master --follow-tags
```

Stable:

```bash
npm version 0.2.0
git push origin master --follow-tags
```

Note:

- `npm version ...` updates `package.json`, creates a commit, and creates a `v...` tag.
- The release workflow publishes only when that tag is pushed.

## CI release guards

The release workflow validates all of the following before publish:

1. Tag format is allowed:
   - `vX.Y.Z`, `vX.Y.Z-alpha.N`, `vX.Y.Z-beta.N`
2. Tag version equals `package.json` version.
3. `CHANGELOG.md` exists.
4. `CHANGELOG.md` contains an entry for the release version.
5. No pending `.changeset/*.md` files remain.

If any check fails, publish is blocked.

## Authentication and security

Use npm Trusted Publishing (OIDC) with GitHub Actions.

Why:

- no long-lived publish token required
- stronger security model than static `NPM_TOKEN`

Required GitHub workflow permission:

- `id-token: write`

Already configured in `.github/workflows/release.yml`.

## Troubleshooting

### Error: unsupported tag format

Cause:

- Tag does not match allowed patterns.

Fix:

- Use `vX.Y.Z`, `vX.Y.Z-alpha.N`, or `vX.Y.Z-beta.N`.

### Error: tag version does not match package.json version

Cause:

- Tag and version drifted.

Fix:

- regenerate tag from the current version (`npm version ...`) or align `package.json` and retag.

### Error: missing changelog entry

Cause:

- `npm run version-packages` was not run/committed.

Fix:

```bash
npm run version-packages
git add .
git commit -m "release: update changelog"
# delete bad tag locally/remotely if needed, then re-tag and push
```

### Error: pending .changeset files found

Cause:

- changesets were not consumed into a release commit.

Fix:

```bash
npm run version-packages
git add .
git commit -m "release: consume changesets"
```

## Optional: verify published versions

Check published versions and dist-tags:

```bash
npm view agemon versions --json
npm dist-tag ls agemon
```

## Quick checklist

Before pushing a release tag:

1. Quality checks pass (`lint`, `typecheck`, `test`, `build`).
2. `npm run version-packages` has been run.
3. `package.json` and `CHANGELOG.md` are committed.
4. No pending `.changeset/*.md` files remain.
5. Correct tag/channel selected (`alpha`, `beta`, or stable).
